# HTTP API 0.3.0-p3 发布与升级说明

P3 补齐账号、文件读取/扫描、任务查询/逐项/重试、持久事件/SSE和结果文件。当前40个操作完整实现，UPL01/DWN01/JOB08保留P2传输子集，其他62个操作仍planned。具体请求见[P3指南](http-api-p3-guide.md)，验收见[记录](http-api-p3-verification.md)。

## 对调用方的变化

- ACC01—ACC09完整开放；凭据PATCH保留缺失字段、null清除、拒绝空字符串。普通更新保留已提交任务绑定的旧版本；清除/删除撤销旧引用。有活动或待核验任务的账号删除返回409。
- 文件目录支持单页读取、字段投影、批量元数据、搜索快照、通配符和扫描。扫描支持完整/部分成功及明确的资源截断。
- 任务与逐项结果有游标分页；列表在原权限检查后计数，时间过滤保留纳秒精度。retry创建新任务，resume延续原传输任务。历史P2提交也重放最初queued回执，当前状态通过GET job查询。
- SSE提供持久事件ID、重连、过期和有界慢消费者处理。已开始的流发生错误时结束流，不追加JSON。
- Artifact提供原任务授权、Range/If-Range/HEAD、完成后24小时TTL、配额和引用保护；删除保留任务摘要。LOC01仅返回授权root ID和状态。
- CLI的ls/search/meta/tree继续共享核心读取解析和聚合。重复页或中途失败明确返回错误，避免将不完整目录显示为全量成功。

## 升级和回滚

服务启动自动从SQLite v1/v2/v3增量迁移到v4，保留账号、配置、任务、检查点、控制回执和版本。新增空Request字段不会改变P2的幂等任务ID或检查点绑定。

升级前应保留一致的数据库及master.key备份；P3结果文件的备份还应包含artifacts目录。P2二进制拒绝打开v4；回滚须恢复升级前一致备份。服务仍要求数据目录独占锁，不允许两个实例同时调度。

可在固定启动配置中显式提供legacy_accounts_file进行只读账号导入；不会自动读取CLI当前账号或改写旧文件。

## 验证范围

本轮相关包race、P2取消/恢复和四个SIGKILL窗口、CLI离线回归、102组实际HTTP契约响应、616条映射和13目标CGO=0构建均通过。其他平台的编译成功不代表目标机运行已经验证。

本轮已使用新扫码会话在`/BaiduPCS-Go-P2-Verification/`内完成真实验收，33个检查阶段及本轮子目录清理通过，见[P3脱敏报告](http-api-p3-upstream-verification.json)。用户授权的凭据保留于本工作区0600的`.env`，由Git忽略且未提交。已有P2真实报告保留其原始范围。完整传输、暂停、暂存和内容代理从P4继续。
