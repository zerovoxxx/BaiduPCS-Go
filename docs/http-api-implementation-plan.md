# BaiduPCS Go HTTP API 分阶段实施计划

日期：2026 年 11 月 2 日。基线：主项目 `1b9131817aaf8ca7dee24bc00e33ebc4c7a5cc73`。工作分支：`codex/http-api-design`。

本计划以[设计方案](http-api-design.md)为目标，以[源码覆盖矩阵](http-api-coverage.md)追踪完整性。当前已完成创建分支、核对远端基线和编写设计资料；尚未开始 HTTP、应用服务或核心代码修改。

## 1 交付顺序和估算

先建立账号、配置、客户端隔离和业务边界，再实现共享任务系统，之后接上传下载与全部写操作。副项目只提供局部参考，不能通过搬入整个 api 目录绕过这些前置工作。

估算单位为工程工作日，假设一名熟悉 Go 的工程师，包含必要测试和文档；外部百度接口调试、上游变化及额外部署环境可能扩大区间。这是排期依据，不是日历承诺。

| 阶段 | 主要产物 | 依赖 | 估算 |
| --- | --- | --- | --- |
| P0 契约和基线 | 契约、源码覆盖清单、行为基准、存储验证 | 当前设计评审 | 2 至 3 日 |
| P1 运行基础和分层 | 组装、配置、客户端工厂、存储、认证、生命周期 | P0 | 4 至 6 日 |
| P2 账号和文件读取 | 账号、凭据、上下文、列表、元数据、搜索、匹配 | P1 | 4 至 5 日 |
| P3 持久化任务 | 调度、事件、结果、取消、重试、扫描 | P1、P2 的边界 | 6 至 8 日 |
| P4 上传下载 | 完整传输参数、检查点、按任务控制、代理下载 | P2、P3 | 7 至 10 日 |
| P5 全部写业务 | 文件写入、分享转存、离线下载、回收站 | P2、P3；下载后续依赖 P4 | 5 至 8 日 |
| P6 其余覆盖和兼容 | 导出、校验、MD5、增量、登录挑战、本地工具 | 对应基础领域及 P4、P5 | 5 至 8 日 |
| P7 完整验收和发布 | 覆盖核对、稳定性、部署资料、版本候选 | 必需能力均完成 | 2 至 4 日 |

总计约 35 至 52 个工程工作日。P6 中的浏览器分片接收、完整 QR/密码挑战属于扩展工作量；可选 xpan、旧 API 路径兼容不计入这一区间。某些历史上游能力若已不可用，交付其能力说明、明确错误和验证证据，不为恢复第三方已移除功能承诺时间。

每个阶段完成即可产生可验证成果。完整 API 以全部可用业务通过验收为准；P2 或 P4 的可用版本不标记为全部覆盖。

## 2 P0 冻结契约和行为基线

### 工作

1. 确认设计中的领域、DTO、路由 ID、所有权和配置生效规则。
2. 将设计目录转为 OpenAPI 3.1.1：每条路由都有输入、成功和错误响应、权限、幂等和能力条件；固定 operationId。
3. 保存 AST 生成的主项目业务清单，核对 CLI 34 个顶层命令、51 个命令节点、86 个参数和 132 个核心导出函数。此处计数不能代替逐项映射。
4. 记录当前 CLI 的关键行为：下载根目录和层级、上传 skip/overwrite/rsync、重试 0、空文件、断点恢复、转存 fs_id、整段分享文本、导出旧格式。
5. 只运行明确可离线的现有测试，网络测试先分类；记录主项目原有失败，不把它们与新改动混淆。
6. 验证 SQLite 驱动及 OpenAPI 工具在目标 Go 和交叉编译环境下的可用性，锁定最少依赖。

### 产物和验收

- `api/openapi/` 契约、请求和响应示例；源码覆盖记录可被重新生成。
- 所有命令参数均有等价字段、表达方式或不支持说明；没有未分类业务入口。
- 异步、分页、文件路径、整数编码、错误和 API principal 与百度账号的区分一致。
- 完整覆盖默认包括主项目所有有效业务；扩展和历史能力单列，不影响统计口径。

### 建议提交

先提交设计和覆盖资料，再单独提交契约。当前设计稿无需自动提交，编码开始时按仓库协作方式处理。

## 3 P1 建立运行基础和依赖边界

### 工作

1. 增加 `server` 子命令和 `internal/bootstrap`，集中组装依赖和信号处理；将 `main.init()` 的 cwd、旧配置初始化和退出副作用移入各模式的显式启动路径。
2. 建立领域错误、账号 ID、文件引用、有效传输选项等最小类型；按调用需求定义 ports。
3. 建立配置仓库和版本，覆盖 PCSConfig 全字段；实现 presence-aware PATCH 和默认值 schema。
4. 建立账号客户端工厂：从凭据和配置快照创建实例，避免借用 ActiveUser 和 CopyPCS 进行隔离。
5. 将 requester 的网络参数应用从进程共享可变状态收拢到客户端或 Transport 工厂；无法立即替换的部分由启动期固定，并禁止请求中热改。
6. 建立 SQLite、秘密存储、数据目录锁和迁移版本；准备任务、事件和幂等表。
7. 实现 Bearer 认证、账号授权、请求 ID、日志脱敏、请求大小限制和错误输出。
8. 实现 SYS01 至 SYS04、SYS08 至 SYS09、CFG01 至 CFG05 和 CFG07；契约随程序内嵌，先提供真实的 planned/implemented 状态。
9. 建立短请求、SSE、内容代理三种期限策略和排空流程，避免把进程退出放进业务服务。

### 验收

- 无百度账号时服务仍能启动，健康和 readiness 含义清楚。
- false、0 和空字符串可被正确配置，非法配置不会部分生效；并发版本冲突返回 412。
- HTTP 层不直接 import pcscommand 或读取 pcsconfig.Config；应用层不 import HTTP 框架。
- 不同客户端工厂实例使用正确的账号和固定网络配置，不发生 Cookie、签名缓存串用。
- 进程关闭可以排空请求并关闭存储；业务代码不会调用 os.Exit。

## 4 P2 完成账号和全部常用读取

### 工作

1. 实现 ACC01 至 ACC09，支持 BDUSS、完整 Cookie、补充凭据和 token-only 状态；凭据只写不回显。
2. 实现旧配置导入和账号映射，覆盖强制用户名后备路径和重复 UID；旧配置不被静默覆盖。
3. 实现 CTX01 至 CTX04、CFG08 至 CFG09，区分客户端 context 与 CLI 默认值。
4. 实现 FIL01 至 FIL04、FIL06、LOC01。
5. 在 baidupcs 中做最小分页扩展以复用当前列表解析；保留原聚合方法。
6. 将 CLI 列表、搜索、元数据、配额和通配符命令逐步改为调用共享服务，终端输出由 CLI 保持。
7. 对依赖百度的读取使用可替换上游适配器，模拟 Cookie 失效、限流和协议异常。

### 验收

- 两个账号、两个调用方同时读取相同路径、修改各自 cwd，彼此不受影响。
- 目录含 1001、2000 和 2001 个条目时，分页和聚合读取正确；上游重复页、空页和中途错误均可判断。
- 元数据的 fs_id 不丢失精度；分片 MD5 状态不被误标成已验证。
- 本地 path、网盘 path、通配符字面量和相对路径处理分别测试。
- 登录状态错误不误用服务 401；账号和配置响应中不含秘密。
- CLI 读取命令的核心结果与迁移前一致。

此阶段提供账号、配置和文件浏览版本。

## 5 P3 建立持久化任务系统

### 工作

1. 实现 JobService、仓库、调度器、资源预算和按目标路径锁。
2. 提交任务、保存幂等记录和创建事件在同一事务完成；调度器扫描持久化队列。
3. 实现 JOB01 至 JOB06、JOB09、JOB11 和 ART01 至 ART04。
4. 实现逐项结果、部分成功、跳过、取消和日志观察者；终态不可被迟到事件覆盖。
5. 实现 SSE、事件保留、Last-Event-ID、心跳和慢客户端处理。
6. 实现 FIL05 文件扫描，覆盖 tree、递归、统计、深度、条目限制和结果分页。
7. 建立启动恢复和 interrupted 状态，区分可安全重试与远端结果未知。

### 验收

- 重复提交同一个 Idempotency-Key 只得到一个逻辑任务；不同 body 返回 409。
- 提交请求断开后，已入库任务仍可查询并继续；取消一个任务不影响另一个任务。
- 在入库后、派发前、执行中和终态持久化时模拟重启，不丢失任务状态，不无限重复执行。
- 未知总量使用 null，部分失败和 skipped 数量正确。
- SSE 可重连、去重、过期回放返回 410；慢消费者不阻塞调度。
- 无并发写同一最终本地文件的路径，队列和内存有上限。

此阶段先用文件扫描和可控假执行器验证任务系统，再接大文件传输。

## 6 P4 完成上传下载和内容代理

### 工作

1. 从 RunUpload/RunDownload 中抽出准备、执行和结果收集流程，保留 CLI 格式化适配。
2. 去除任务流程中的 signal.Notify、os.Exit、全局停止和 stdout 依赖；将 TaskUnit 对 pcsconfig.Config、全局限速与 HTTP 客户端的隐式读取改为注入有效运行环境，同时注入进度观察者和 JobControl。
3. 给上传断点增加账号、目标路径和文件指纹命名空间，统一管理数据库实例或 checkpoint store。
4. 实现 UPL01 至 UPL04、DWN01 至 DWN05、JOB07 至 JOB08。
5. 保留最新上传握手、-9 分支、秒传检查、norapid 断点、分片校验和优雅停止行为。
6. 实现三种下载模式、正确的线程预算与文件并发、目录层级、空目录、覆盖和文件有效性校验。
7. 接入底层 downloader 的按实例控制；上传暂停使用按任务的分片边界停止并重新创建执行器恢复。
8. 实现暂存引用、接收大小限制、取消清理、磁盘不足和结果提交。
9. 实现内容代理和短期票据，处理 Range、HEAD、重定向、请求取消与超时。

### 验收

- 上传单文件、多目录、空文件、重复文件及 skip/overwrite/rsync 结果正确；恢复断点不误用另一个账号或目标。
- 上传 `skip_rapid_check` 两种路径均验证中断恢复；源文件大小、mtime、摘要变化时明确拒绝旧检查点。
- 取消或暂停 A 后 B 可继续，新提交 C 可以启动；全局停止不会永久污染后续任务。
- 下载 /a/x 和 /b/x 不被扁平化覆盖；空目录、完整路径、mtime 和权限选项正确。
- retry=0、显式 verify=true/false、全局 no_check 默认值的优先级正确。
- 同名 multipart 并发不会互相覆盖，任务完成前暂存文件不被删除。
- 代理覆盖 GET、HEAD、206、416、断连、慢流、错误响应和重定向主机检查；Cookie 不进入 URL 和日志。
- CLI 上传失败仍返回非零退出码，正常跳过不当作失败；CLI 下载行为回归通过。

此阶段提供完整本地传输版本。NoSplitFile 真正实现前仍明确拒绝 true，不能为覆盖字段而假报功能成功。

## 7 P5 完成文件写入和网盘业务

### 工作

1. 实现 FIL07 至 FIL11：目录创建、删除、复制、移动和重命名。
2. 实现 SHR01 至 SHR04：分享创建、列表、详情、带码链接和批量取消。
3. 从主项目最新 RunShareTransfer 抽出可返回结果的转存服务，实现 TRF01 至 TRF02。
4. 实现 OFF01 至 OFF07、REC01 至 REC04。
5. 接入 JOB10 的按操作核对逻辑，覆盖结果未知的远端写操作。
6. 转存后下载建立子任务和有界可见性检查，取消父任务不隐藏已发生的远端修改。
7. 修改成功或部分成功后，失效账号和路径相关缓存。

### 验收

- 多源复制和移动、目标存在/不存在、文件与目录冲突和重命名语义与主项目一致。
- 分享 period、提取码生成和 combined_link 的含义正确；批量取消部分失败可查。
- 整段分享文本、URL pwd、独立提取码、fs_id 指定、collect 和 download_after 都有测试。
- 百度离线 ID 与本地 job ID 不混用，取消和删除百度任务返回可核对结果。
- 回收站恢复返回实际成功 fs_id，永久删除和清空返回逐项或总数结果。
- 远端写操作在响应丢失后不会盲目自动重放；核对失败保留 interrupted 和明确原因。
- 对已发生的远端修改，取消请求不伪报事务回滚。

## 8 P6 补齐剩余能力和兼容工具

### 工作

1. 实现 INT01 至 INT06、EXP01，覆盖本地摘要、远端摘要、MD5 修复、文件验证和全部导出参数。
2. 实现 FIL12 的增量适配，处理 cursor、has_more、reset 和上游不可用情况。
3. 实现 LOG01 至 LOG06；参考副项目 QR 流程，补齐会话所有权、秘密存储、过期和状态转换。
4. 迁移主项目密码登录流程中可服务化的验证码、手机/邮箱验证步骤；未支持的 challenge 明确反馈。
5. 实现 LOC02 至 LOC03、SYS05 至 SYS06、CFG06，覆盖本地加解密、网络诊断和受控配置重载。
6. 实现 UPL05 至 UPL09 的浏览器断点接收，区别于到百度的分片断点。
7. 对旧式秒传、Rname、SuperTransfer、NoSplitFile 和导出限制保存真实能力结论，更新文档与 capabilities。

### 验收

- checksum 的长度、MD5、256 KiB 切片 MD5、CRC32 与现有工具一致，包括空文件和大文件。
- 导出 root、recursive、retry、format、结果文件和部分失败均可使用；旧格式不被标记成可成功还原的保证。
- MD5 修复遇到目录、不支持文件、缺失头字段和上游未刷新时有稳定错误。
- QR 会话不能跨调用方使用，过期后交换凭据失败且不留下明文秘密。
- 加解密默认不删除源文件，显式删除仅在结果提交成功后执行；gzip 行为兼容。
- 接收分片 offset 冲突返回 409，接收结束前不产生可用 staged_file_id；重启后可核对偏移。
- 目录增量和历史能力逐项有上游验证结果，无法使用的能力不计入 available。

主项目不存在的 xpan HTTP 路由和副项目旧路径兼容属于可选后续范围。若加入，独立调整排期，不混入“主项目所有接口已覆盖”的必需清单。

## 9 P7 完整性验收和发布候选

### 工作

1. 对照源码覆盖矩阵逐项核销：业务入口、参数、配置、底层方法和历史处理结论全部对应当前代码。
2. 完成 OpenAPI 与实际路由和 DTO 的契约核对、CLI 回归和 race 检查。
3. 在可控测试账号和专用测试目录运行真实百度集成验收，覆盖普通和目标部署所需账号类型；不使用用户正常文件做破坏性验证。
4. 进行多账号、多任务、取消恢复、重启、磁盘不足、网络异常和大目录稳定性验证。
5. 补齐 server 启动、API token、账号导入、配置迁移、数据备份、日志、反向代理和关闭说明。
6. 产生版本候选和迁移说明，记录全部未验证或上游不可用能力。

### 发布门槛

- 所有有效且上游可用的主项目业务能力有公开契约和验收证据，不能用“有路由”代替可用。
- CLI 行为、上传断点恢复、目录分页等主项目近期修复保持有效。
- HTTP 和应用层依赖方向符合设计，多个入口共享业务流程。
- 任务状态、分项结果和事件没有已知导致丢任务或跨任务取消的问题。
- 账号、Cookie、代理秘密、票据和本地根目录隔离检查通过。
- 记录源码映射率、实现率、离线验证率、上游实测率四个独立指标和未通过项。

## 10 测试组织

| 测试层 | 重点 | 不依赖真实百度 |
| --- | --- | --- |
| 领域和参数 | 选项优先级、状态迁移、路径、策略和错误分类 | 是 |
| 应用服务 | 模拟 ports，验证业务结果、并发隔离和部分成功 | 是 |
| HTTP 契约 | httptest、权限、JSON、HTTP 状态、分页、幂等和 SSE | 是 |
| 百度适配 | 受控 HTTP 上游返回码、分页、头字段、重定向和异常响应 | 是 |
| 传输和持久化 | 受控本地服务、分片、Range、故障注入和重启恢复 | 是 |
| CLI 回归 | 共享服务后的参数映射、输出要点和退出码 | 主要是 |
| 真实上游集成 | 账号、真实业务和账号类型限制 | 否，显式配置后运行 |

真实上游测试单列运行，不混进默认 `go test ./...` 的快速验证。传输控制和持久化检查使用能发现跨账号、跨任务或断点误用的情景测试；不为每个 setter 编写镜像实现的测试。

| 9 | 分享转存和后续下载 | 最新 fs_id、分享文本和任务依赖 |
| 10 | 校验、导出、增量、登录和本地工具 | 历史能力、条件功能和秘密生命周期 |
| 11 | 全量核对、稳定性和发布资料 | 覆盖证据、部署与迁移 |

这些变更单元表达依赖和审查边界，不要求创建独立微服务或一次性改写全部 CLI。每次从 CLI 抽出业务流程时，同步保持对应命令的参数和退出行为。

## 12 主要风险和处理

| 风险 | 处理方式 | 发现阶段 |
| --- | --- | --- |
| 百度接口或账号限制变化 | capability 状态、受控集成测试、适配器隔离 | P0 起，P7 汇总 |
| 全局配置或浅拷贝造成串账号 | 快照和独立工厂，尽早做并发验证 | P1、P2 |
| 全局停止污染后续任务 | JobControl、按任务注册执行句柄 | P3、P4 |
| 旧上传断点缺少账号和目标信息 | 新命名空间；旧记录核对后迁移 | P4 |
| 业务抽取改变 CLI 行为 | 原行为基准、同阶段回归 | P0 起 |
| 远端请求成功但本地未确认 | interrupted、按操作核对、限制自动重放 | P3、P5 |
| 目录遍历、日志和事件占用无限资源 | 分页、任务限额、有界事件和保留策略 | P2、P3 |
| 历史字段看似支持但实际无效 | 覆盖矩阵、显式错误、独立验证 | P0、P6 |

## 13 当前讨论的默认决策

本设计默认单服务实例、同 module、标准库 HTTP、SQLite 元数据、按请求指定账号、调用方独立 context、全部长操作进入 job、凭据只写和显式本地根目录。保持主项目代码和参数覆盖，优先服务化其有效业务流程。

具体 SQLite 驱动和契约工具在 P0 验证；目标平台与实际部署资源在 P0 转为明确验收矩阵。分布式多实例、多租户计费、外部身份提供商、任务 Webhook、xpan 和副项目旧路径兼容均作为后续可选需求，不延迟当前必需业务的分层实现。
