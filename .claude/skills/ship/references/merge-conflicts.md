# 合并与 rebase 冲突处理

仅在对齐远端时出现未合并路径后读取。目标是保留双方意图、避免数据丢失，并让验证覆盖真正要落地的集成结果。

## 1. 固定现场

1. 记录操作前的本地 `HEAD`、目标分支 tip、`git status --short --branch`，以及：

   ```bash
   git diff --name-only --diff-filter=U
   ```

2. 逐个处理冲突文件，不批量执行 `git checkout --ours .`、`git checkout --theirs .`、reset 或清理未跟踪文件。
3. 需要理解三方差异时分别查看 stage 1 / 2 / 3：

   ```bash
   git show ":1:path/to/file"  # merge base；add/add 时可能不存在
   git show ":2:path/to/file"  # ours
   git show ":3:path/to/file"  # theirs
   ```

   **rebase 中 ours 通常是目标分支当前结果，theirs 才是正在重放的本地提交。** 不根据名称猜意图，必须结合原提交和 base 判断。

## 2. 冲突分级

### 生成物

- 从仓库脚本、构建清单或 CI 找到权威生成命令，先合并生成输入，再完整重生成输出。
- 不手工拼接生成文件，也不把 lockfile、API client、编译产物等简单选为某一侧。
- 生成器失败时自主定位并修复；无法找到入口或仍有漂移时保留可恢复现场，记录验证缺口并继续独立工作，不能把不确定生成物标记为已解决。

### 顺序编号资源

本节用于项目声明的 migration / 发布序号，不用于稳定需求 ID。

- 保留已进入目标分支的编号，本地尚未推送的资源顺延到下一个未占用编号。
- 同步文件名、文件内标识、父链 / 依赖关系、清单、SPEC 与仓库内引用。
- 从项目规则、文件名和引用链推断适用编号，检查唯一性和链接；没有现成校验器时可用针对性检查验证，不因此要求用户决定本地编号。

### 源代码、配置与文档语义

1. 分别说明 base → 目标分支和 base → 本地提交各自改变了什么，以及两者是否修改同一业务不变量。
2. 不整文件选择 ours / theirs。结合双方意图、当前请求、相关实现和测试，自主合并可恢复的本地修改，并验证双方需要保留的行为。
3. delete/modify、rename/rename、产品口径或二进制冲突本身不引入审批闸门。先保留两侧原始内容，形成候选 diff 并标注假设；尚不能确定的事实可询问，同时继续独立工作。
4. 仅在下一步会不可恢复地丢弃一侧数据、执行破坏性迁移或改写已发布结果，且尚未授权时暂停该动作。请求确认时给出路径、双方意图、候选结果、验证与恢复说明，不把大段冲突标记直接丢给用户。

### 需求文档与清单文件

- 只合并 SPEC / PLAN 本身，合并后运行同级 spec skill 的 `scripts/spec_workflow.py list --root <项目根目录>` 校验；不按需求顺序改名。
- 短 ID 碰撞由校验器报错，为新建冲突需求重生成 ID 并修正引用，保留目标分支的需求。
- 非派生清单独立新增的条目默认两边都保留，不整表选边。
- 删除条目与修改条目相撞时，从提交和引用判断删除意图；缺少证据先保留可恢复的候选，不默认等待用户裁决。
- 排序、链接和派生清单在内容合并后重新生成或机械整理。

## 3. 继续前验证

1. 确认没有未合并路径和冲突标记：

   ```bash
   test -z "$(git diff --name-only --diff-filter=U)"
   git diff --check
   ```

2. 检查 `git diff` / `git diff --cached`，只暂存已解决的目标文件，不夹带原工作区的其他改动。
3. 为双方原意运行聚焦测试；生成物重跑漂移检查，编号资源重跑唯一性 / 链路检查。
4. rebase / merge 完成后运行受影响质量门；跨模块契约或项目要求时执行完整回归。冲突前未覆盖最终内容和基线的结果不能复用。

## 4. 无法安全继续

- 本次自行启动的操作无法安全继续时，保留候选 diff，再用匹配的 `git rebase --abort` 或 `git merge --abort` 恢复，检查分支、原 `HEAD` 与工作区变更后报告实际缺口；不擅自中止用户原有的进行中操作，也不停止独立的本地检查。
- 不删除自动 stash 或用户 stash。自动恢复失败时保留 stash，报告其引用与恢复命令，不强行覆盖工作区。
- 同一远端竞态最多重新对齐两轮；持续被推进时保留本地候选并报告实际缺口，继续独立检查，不进入无限重试或重复批准循环。
