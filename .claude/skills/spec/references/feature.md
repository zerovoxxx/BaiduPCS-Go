# 新功能方案

读取时机：`spec` 第 1 步判定为新功能（已有项目上新增或改变行为，也是未说明类型时的默认）后。决策确认与调研遵循 [design-tradeoffs.md](design-tradeoffs.md)。

## 方案步骤

1. 理解需求。
2. 现状摸底：相似功能、现有分层、可复用的代码和测试。代码能回答的不问用户。
3. 范围挑战：现有代码能解决多少、最小改动集是什么、哪些可以延后。预计改 8 个文件以上或新增 2 个以上服务时必做。
4. 影响面与存量兼容：波及谁、数据迁移、旧接口、灰度开关、回滚。
5. 外部调研：按 `design-tradeoffs.md` 的调研规则，新功能只在有难以回退的决策或用户要求时做。
6. 方案：遵守 `架构地图` 和 `项目红线`，要打破时按决策分级处理；图解能帮助说明方案时，使用 `archify`。
7. 详细设计：根据实际任务选用专项 skill。新的数据模型或迁移设计使用 `db-design`；交互可沿用现有组件时直接说明，需要探索原型或做视觉评审时再用 `huashu-design`。

`架构地图` 为空或没有涉及模块时，先把本次需要的事实整理在 SPEC 或报告里；可按 [claude-md-guide.md](../../harness-init/references/claude-md-guide.md) 的「入口回写边界」给出写入位置和候选内容，取得用户明确决策及写入要求后再更新入口。

专项 skill 按任务需要选用，用户指定或排除优先，不绑定工作类型或阶段。
