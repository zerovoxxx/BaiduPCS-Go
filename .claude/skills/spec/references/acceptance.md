# 用户可见能力的验收口径

读取时机：目标或验收标准声明用户能看到、操作或完成某个流程（页面、CLI 输出、通知等）时。`plan`、`dev`、`ship` 在核对这类验收项时也按本口径。

1. 数据 / 接口产出与用户可见结果写成独立验收项；前者通过不代表后者已交付。
2. 写明用户在什么位置执行什么动作、看到什么值或状态，避免只写“输出某字段”“增加某能力”这类无法定位呈现层的描述。
3. 验证证据与声明处于同一层级：API 或单元测试不能单独证明页面已展示；优先用页面级、组件级或端到端断言验证实际渲染值、状态或交互结果。纯视觉变化按项目约定使用带预期对照的截图或明确的手动步骤。
4. 新增断言必须能在实现缺失时失败，而不只检查标签、容器或控件存在；高风险行为用 TDD 的先失败记录，或一次针对性负向校验证明测试有效。
5. 每条用户可见验收项都能追溯到 `变更范围` 中的实现位置和 `验证计划` 中的证据；任一映射缺失，SPEC 就还没写完整。

下游约定：`plan` 为这类验收项安排消费端实现任务和呈现层断言；`dev`、`ship` 完成前逐条核对同层级证据。
