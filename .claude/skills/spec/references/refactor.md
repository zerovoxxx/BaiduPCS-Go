# 重构方案

读取时机：`spec` 第 1 步判定为重构（目标写明行为不变，只调整结构或依赖）后；依赖升级归入这一类。决策分级见 [design-tradeoffs.md](design-tradeoffs.md)。

## 方案步骤

1. 明确哪些行为不能变，写进非目标和验收标准。
2. 找测试缺口：现有测试不足时，第一个任务先补测试锁定行为。
3. 拆成小步，每步可验证。
4. 重构和行为变更分开；发现要改行为时按决策分级处理。
5. Python/uv 项目升级直接依赖时，方案里写明用 `py-dep-upgrade`；用户只要求检查或升级依赖、且不需要整体重构方案时，可直接使用该 skill。

专项 skill 按任务需要选用，用户指定或排除优先，不绑定工作类型或阶段；重构涉及表结构、迁移或需要图解时，同样可用 `db-design`、`archify`。
